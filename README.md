# SBOM Enricher

Версия `v.1.0.0`.

[Запуск](#быстрый-запуск) · [Сверка SBOM](#сверка-sbom-с-astra-linux) · [Все снимки Astra](#снимки-astra-linux) · [Лицензия](#лицензия)

Локальный инструмент для сверки компонентов из DOCX и SBOM с каталогами Astra Linux Special Edition.

## Что умеет проект сейчас

* импортировать package-index файлы Astra Linux в SQLite;
* хранить несколько семейств и подвёрсий Astra, включая ветки `1.6.x`, `1.7.x` и `1.8.x`;
* проверять входной `.docx` с таблицей `component | version` сразу против нескольких выбранных версий ОС;
* формировать Excel-отчёт по результатам проверки DOCX;
* сверять SBOM CycloneDX 1.6 и 1.7, исправлять версии и добавлять отметки Astra с сохранением оригинала;
* сравнивать две выбранные ОС между собой по составу компонентов;
* показывать состав семейства версий одной ОС, например ветки `1.8.x`.

## Сценарий проверки DOCX

1. Подготовить package-index файлы Astra и положить их в `data/raw/astra/`.
2. Обновить локальную базу SQLite через импортёр.
3. Запустить сайт. 
4. Загрузить входной `.docx` и выбрать нужные версии ОС.
5. Просмотреть результат в браузере и скачать итоговый `.xlsx`.

## Формат входных данных

### 1. Каталоги Astra Linux

Проект ожидает текстовые package-index файлы в папке:

```text
data/raw/astra/
```

Поддерживаются снимки базовых выпусков и их обновлений. Примеры имён:

```text
1.6.0-main.txt
1.6.0-contrib.txt
1.6.0-non-free.txt
1.7.0-main.txt
1.7.0-contrib.txt
1.7.0-non-free.txt
1.8.0-main.txt
1.8.0-contrib.txt
1.8.0-non-free.txt
1.8.0-non-free-firmware.txt
1.8.1.6-main.txt
1.8.1.6-contrib.txt
1.8.1.6-non-free.txt
1.8.1.6-non-free-firmware.txt
1.8.2.7-main.txt
1.8.3.8-main.txt
```

Рекомендуемая схема имени файла:

```text
<os_version>-<repository>.txt
```

Где `repository` обычно один из:

* `main`
* `contrib`
* `non-free`
* `non-free-firmware`

### 2. Входной Word-файл

Во входном `.docx` должна быть ровно одна таблица с колонками:

```text
component | version
```

Пример:

| component         | version     |
| ----------------- | ----------- |
| openssl           | 3.0.17-alt1 |
| postgresql server | 15.6        |
| nginx             | 1.24.0      |

## Быстрый запуск

Установите Python 3.11 или новее. Для установки зависимостей нужен интернет. Распакуйте архив или клонируйте репозиторий в папку с правом записи.

| Система | Команда из папки проекта |
| --- | --- |
| macOS, включая Apple Silicon | `./run_local.command` |
| Windows | `.\run_local.bat` |

Оба файла также можно открыть двойным щелчком. На macOS при необходимости восстановите право запуска командой `chmod +x run_local.command`.

Сценарий создает локальное окружение `.venv`, устанавливает зависимости, импортирует включенные каталоги и запускает приложение. Когда сервер запустится, откройте <http://127.0.0.1:8000/sbom>. Для остановки нажмите Ctrl+C в окне запуска. Если порт 8000 занят, укажите другой через переменную окружения `CERT_CHECKER_PORT`.

## Как обновить базу при добавлении новых версий Astra

Если ты добавил новые файлы `1.6.x`, `1.7.x`, `1.8.x`, то:

1. скопируй их в `data/raw/astra/`;
2. при желании удали старую базу для полностью чистой пересборки:

```text
data/db/certchecker.sqlite3
```

3. снова запусти импорт:

```powershell
.\.venv\Scripts\python.exe .\scripts\import_astra.py
```

## Что есть в интерфейсе

### Работа с DOCX

Режим для загрузки входного Word-файла и проверки его против выбранных версий Astra Linux.

Основные возможности:

* выбор нескольких целевых версий ОС;
* просмотр сводной статистики по результату;
* просмотр таблицы найденных и ненайденных компонентов;
* скачивание Excel-отчёта.

### Сравнение ОС

Режим для сравнения двух каталогов между собой:

* какие компоненты совпадают полностью;
* где версии различаются;
* какие компоненты есть только слева или только справа.

### Семейство версий

Режим просмотра одной ветки версий, например:

* `1.6.x`
* `1.7.x`
* `1.8.x`

Показывает состав компонентов по всем доступным подвёрсиям внутри выбранного семейства.

## Отчёты

Итоговый Excel-отчёт содержит минимальные бизнес-колонки:

* `component`
* `version`
* выбранные версии ОС

Идея проекта такая:

* Excel — для передачи результата;
* web UI — для подробной диагностики и просмотра различий.

## Ограничения текущей версии

Пока ещё не реализовано:

* импорт ALT Linux;
* импорт Red OS;
* единый отчёт сразу по нескольким семействам ОС;
* окончательно вычищенная и стабилизированная UI-логика для всех тяжёлых таблиц на очень больших наборах данных.

## Практические замечания

* Для сертифицированных ISO Astra обычно достаточно извлекать из образа каталог `DISTS` и брать из него файлы `PACKAGES`, а не хранить весь ISO целиком.
* Для обычной пересборки каталога вручную в SQLite ничего писать не нужно: проект уже использует отдельный импортёр `scripts/import_astra.py`.
* Если после обновления файлов в `data/raw/astra/` в интерфейсе видны старые данные, проще всего удалить `data/db/certchecker.sqlite3` и выполнить импорт заново.

## Сверка SBOM с Astra Linux

Откройте <http://127.0.0.1:8000/sbom>. Загрузите CycloneDX JSON 1.6 или 1.7 в UTF-8 (до 64 МиБ) и выберите снимок Astra. Зеленым показано точное совпадение имени и полной версии пакета. Желтым показано расхождение версии, в том числе для уже указанной Astra. Красным показана отметка Astra, для которой пакет в выбранном каталоге не найден. Совпадение означает наличие пары в импортированных индексах. В карточках показано число уникальных имен пакетов основного каталога. Если пакет из основного состава присутствует в фиксированном репозитории обновлений, для той же архитектуры при сверке используются версии обновления. Новые имена из репозитория обновлений не расширяют основной состав.

1. В таблице отметьте пакеты, которым нужно добавить Astra. «Принять все» выбирает только точные совпадения.
2. Для желтой строки в колонке «Какую версию оставить» можно сохранить исходную версию или выбрать версию из каталога. После выбора версии Astra ее можно отдельно отметить как предоставленную Astra. Выбирайте версию каталога только при подтверждении, что именно этот пакет используется.
3. Подтвердите происхождение отмеченных пакетов и, если меняли версии, соответствие связанных данных. Нажмите «Применить». Приложение сохранит отдельную копию и покажет число добавленных отметок и измененных версий. С этой копией можно продолжить работу.
4. Нажмите «Скачать измененный SBOM». Кнопка «Скачать оригинал» возвращает исходный файл побайтово.

Приложение добавляет `{"name":"GOST:provided_by","value":"Astra Linux Special Edition"}` в массив `properties` отмеченных компонентов. Уже заполненные свойства поставщика сохраняются. При смене версии обновляются `version` и версия в `purl`, а `bom-ref` и ссылки на него сохраняются. Для компонентов с хешами или другими привязанными к артефакту идентификаторами замена версии через интерфейс недоступна. Подписанные SBOM доступны для просмотра. Оригиналы и сохраненные редакции находятся в `data/uploads/sbom/`.

Для полной проверки выгрузки используйте установленный SBOM Checker ИСП РАН:

```sh
python /путь/к/sbom-checker/sbom-checker.py /путь/к/sbom-astra.json --format oss
```

Для перечня образов контейнеров используйте `--format container`. Приложение проверяет структуру, необходимую для сверки, и формат добавляемого свойства. Прочие требования ФСТЭК проверяются отдельно.

## Снимки Astra Linux

В комплекте **25 снимков Astra Linux Special Edition x86-64** и 127 индексных файлов. В таблице перечислены все версии, которые появятся после импорта.

| Ветка | Снимки из исходного проекта | Снимки из фиксированных репозиториев Astra |
| --- | --- | --- |
| 1.6 | `1.6.0` | |
| 1.7 | `1.7.0`, `1.7.9.41` | `1.7.0`, `1.7.1`, `1.7.2`, `1.7.3`, `1.7.4`, `1.7.5`, `1.7.6`, `1.7.7`, `1.7.8`, `1.7.9`, `1.7.10`, `1.7.11` |
| 1.8 | `1.8.0`, `1.8.1.6`, `1.8.2.7`, `1.8.3.8` | `1.8.1`, `1.8.2`, `1.8.3`, `1.8.4`, `1.8.5`, `1.8.6`, `1.8.7` |

`1.7.0` есть в обеих колонках и отображается одной карточкой. Для `1.7.1`–`1.7.11` включены индексы фиксированных репозиториев обновлений. URL и SHA-256 всех 97 загруженных индексов указаны в [реестре источников](data/raw/astra/SOURCES.tsv).

- [Официальные репозитории Astra Linux SE 1.7](https://wiki.astralinux.ru/pages/viewpage.action?pageId=323673537)
- [Официальные репозитории Astra Linux SE 1.8](https://wiki.astralinux.ru/pages/viewpage.action?pageId=323662823)
- [Сертификаты и сведения об исполнениях Astra Linux](https://astra.ru/info/certificates-licenses/)
- [Навигатор официальных репозиториев Astra Linux](https://packages.astralinux.ru/search/binary/)

Номера в интерфейсе обозначают снимки каталогов. Ветки свернуты в группы, а результаты можно фильтровать по статусу, связи с Astra и тексту. Повторная сверка другого снимка использует уже загруженный файл, если новый не выбран. Сертификат относится к ОС и указанным в нем исполнениям и обновлениям. Покрытие ограничено перечисленными индексами, без полного архива оперативных обновлений, расширенных репозиториев и других архитектур. Для дополнительного снимка используйте индекс Packages нужного релиза из официального репозитория или из поставленного вам образа, распакуйте его в `data/raw/astra/<версия>-<репозиторий>.txt` и повторите импорт. Для воспроизводимой сверки используйте фиксированный индекс нужного релиза.

Для 1.7.0 три скачанных индекса основного репозитория совпали по SHA-256 с тремя файлами из исходного архива. В них 3 135 записей `main`, 6 `contrib` и 197 `non-free`. Выдача навигатора в локальный каталог не импортировалась. Для формальной сверки состава сертифицированной поставки сопоставьте каталог с индексом конкретного поставленного ISO и документацией на исполнение.

Контрольный подсчет для 1.7.0: в официальном `repository-base` 13 546 записей `main`, 6 `contrib` и 240 `non-free`. Сумма по `repository-main` и `repository-base` составляет 17 130 записей до устранения дублей. Это объясняет возможный порядок величины выдачи навигатора. Состав для сверки определяет `repository-main`. `repository-base` и `repository-extended` исключены.
