# Cert Checker

Локальный инструмент для проверки перечня программных компонентов из входного Word-файла против каталога компонентов сертифицированных сборок Astra Linux.

## Что умеет проект сейчас

* импортировать package-index файлы Astra Linux в SQLite;
* хранить несколько семейств и подвёрсий Astra, включая ветки `1.6.x`, `1.7.x` и `1.8.x`;
* проверять входной `.docx` с таблицей `component | version` сразу против нескольких выбранных версий ОС;
* формировать Excel-отчёт по результатам проверки;
* сравнивать две выбранные ОС между собой по составу компонентов;
* показывать состав семейства версий одной ОС, например ветки `1.8.x`.

## Текущий сценарий работы

1. Подготовить package-index файлы Astra и положить их в `data/raw/astra/`.
2. Обновить локальную базу SQLite через импортёр.
3. Запустить сайт. 
4. Загрузить входной `.docx` и выбрать нужные версии ОС.
5. Просмотреть результат в браузере и скачать итоговый `.xlsx`.

## Формат входных данных

### 1. Каталоги Astra Linux

Проект ожидает текстовые package-index файлы в папке:

```text
data/raw/astra/
```

Поддерживаются как базовые ветки, так и сертифицированные подвёрсии. Примеры имён:

```text
1.6.0-main.txt
1.6.0-contrib.txt
1.6.0-non-free.txt
1.7.0-main.txt
1.7.0-contrib.txt
1.7.0-non-free.txt
1.8.0-main.txt
1.8.0-contrib.txt
1.8.0-non-free.txt
1.8.0-non-free-firmware.txt
1.8.1.6-main.txt
1.8.1.6-contrib.txt
1.8.1.6-non-free.txt
1.8.1.6-non-free-firmware.txt
1.8.2.7-main.txt
1.8.3.8-main.txt
```

Рекомендуемая схема имени файла:

```text
<os_version>-<repository>.txt
```

Где `repository` обычно один из:

* `main`
* `contrib`
* `non-free`
* `non-free-firmware`

### 2. Входной Word-файл

Во входном `.docx` должна быть ровно одна таблица с колонками:

```text
component | version
```

Пример:

| component         | version     |
| ----------------- | ----------- |
| openssl           | 3.0.17-alt1 |
| postgresql server | 15.6        |
| nginx             | 1.24.0      |

## Быстрый запуск на Windows

### Вариант 1. Полный запуск через bat

Запусти:

```powershell
run_local.bat
```

Обычно этот сценарий:

* создаёт виртуальное окружение;
* устанавливает зависимости;
* импортирует каталоги Astra в SQLite;
* запускает сайт;
* открывает браузер.

### Вариант 2. Ручной запуск по шагам

#### 1. Создать виртуальное окружение

```powershell
python -m venv .venv
```

#### 2. Установить зависимости

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

#### 3. Обновить базу компонентов Astra

```powershell
.\.venv\Scripts\python.exe .\scripts\import_astra.py
```

Запасной вариант:

```powershell
.\.venv\Scripts\python.exe -m scripts.import_astra
```

#### 4. Запустить сайт

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

#### 5. Открыть в браузере

```text
http://127.0.0.1:8000
```

## Как обновить базу при добавлении новых версий Astra

Если ты добавил новые файлы `1.6.x`, `1.7.x`, `1.8.x`, то:

1. скопируй их в `data/raw/astra/`;
2. при желании удали старую базу для полностью чистой пересборки:

```text
data/db/certchecker.sqlite3
```

3. снова запусти импорт:

```powershell
.\.venv\Scripts\python.exe .\scripts\import_astra.py
```

## Что есть в интерфейсе

### Работа с DOCX

Режим для загрузки входного Word-файла и проверки его против выбранных версий Astra Linux.

Основные возможности:

* выбор нескольких целевых версий ОС;
* просмотр сводной статистики по результату;
* просмотр таблицы найденных и ненайденных компонентов;
* скачивание Excel-отчёта.

### Сравнение ОС

Режим для сравнения двух каталогов между собой:

* какие компоненты совпадают полностью;
* где версии различаются;
* какие компоненты есть только слева или только справа.

### Семейство версий

Режим просмотра одной ветки версий, например:

* `1.6.x`
* `1.7.x`
* `1.8.x`

Показывает состав компонентов по всем доступным подвёрсиям внутри выбранного семейства.

## Отчёты

Итоговый Excel-отчёт содержит минимальные бизнес-колонки:

* `component`
* `version`
* выбранные версии ОС

Идея проекта такая:

* Excel — для передачи результата;
* web UI — для подробной диагностики и просмотра различий.

## Ограничения текущей версии

Пока ещё не реализовано:

* импорт ALT Linux;
* импорт Red OS;
* единый отчёт сразу по нескольким семействам ОС;
* окончательно вычищенная и стабилизированная UI-логика для всех тяжёлых таблиц на очень больших наборах данных.

## Практические замечания

* Для сертифицированных ISO Astra обычно достаточно извлекать из образа каталог `DISTS` и брать из него файлы `PACKAGES`, а не хранить весь ISO целиком.
* Для обычной пересборки каталога вручную в SQLite ничего писать не нужно: проект уже использует отдельный импортёр `scripts/import_astra.py`.
* Если после обновления файлов в `data/raw/astra/` в интерфейсе видны старые данные, проще всего удалить `data/db/certchecker.sqlite3` и выполнить импорт заново.
